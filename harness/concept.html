Chapter 01

하네스의 개념

코딩 에이전트에게 일을 맡기면 파일이 열리고, 코드가 고쳐지고, 테스트가 돈다. 이 일을 모두 모델이 하는 것처럼 보이지만, 모델은 다음 토큰을 내놓을 뿐이다. 파일을 실제로 여는 것, 무엇을 읽힐지 고르는 것, 위험한 명령을 막는 것, 결과를 확인하는 것은 모델 바깥의 장치가 한다. 이 장에서는 그 바깥 장치 전체를 하네스(harness)라고 부르고, 여섯 구성요소로 나누어 본다.

이 장에서 배우는 것
  • 에이전트 = 모델 + 하네스라는 정의를 설명하고, 하네스의 대표 구성요소 여섯 가지를 말할 수 있다.
  • 도구가 기본으로 주는 부분(도구 실행·권한·문맥 불러오기)과 사용자가 더하는 부분(규칙·스킬·훅·검사 도구)을 구분할 수 있다.
  • 프롬프트 엔지니어링 ⊂ 컨텍스트 엔지니어링 ⊂ 하네스 엔지니어링의 포함 관계를 설명할 수 있다.

01에이전트 = 모델 + 하네스

정의는 Böckeler(2026)를 따른다. 하네스는 코딩 에이전트에서 모델을 뺀 모든 것이다. 모델은 Claude나 GPT 같은 대규모 언어모델(LLM)이고, 하네스는 그 모델이 실제 작업을 하도록 둘러싼 나머지 전부다. Claude Code, Codex 같은 도구가 대표적인 하네스다.

규칙과 스킬의 차이
규칙은 매번 읽는 규칙 문서(CLAUDE.md 등)이고, 스킬은 해당 작업을 할 때만 불러 읽는 지침이다. 둘 다 모델이 읽는 설명서라는 점은 같지만, 문맥에 머무는 시간이 다르다. 이 차이는 2장의 문맥 길이 문제와 바로 이어진다.

    03용어의 확장

    하네스 엔지니어링은 갑자기 나온 말이 아니다. 한 번의 지시문을 다듬던 기술이, 모델이 보는 입력 전체를 고르는 기술로, 다시 모델 밖의 모든 장치를 설계하는 기술로 넓어졌다. 세 단계는 앞의 것을 감싸며 넓어진 것이고, 컨텍스트는 하네스의 일부다.

    04이미 쓰고 있는 하네스

    아래 도구 가운데 하나라도 쓰고 있다면, 이미 하네스를 쓰고 있는 것이다. 어떤 모델을 쓰든, 모델이 파일을 열고 명령을 실행하게 해 주는 부분은 이 도구들이 맡는다.

    Claude CodeCodexCursorGemini CLIKiro (AWS)

    Kiro는 AWS의 에이전트 코딩 도구(IDE·CLI)로, 2026년 5월 Amazon Q Developer를 대체했다.

    기성품 하네스는 도구 실행, 권한, 문맥 불러오기를 기본으로 준다. 규칙·스킬, 훅, 검사 도구는 비어 있거나 최소한으로만 들어 있고, 여기에 무엇을 더할지는 사용자의 몫이다. 다음 장은 가장 쉬운 방법, 즉 규칙을 글로 많이 적어 넣는 방법이 어디서 한계에 부딪히는지 본다.

    확인 퀴즈

    Q1Böckeler(2026)의 정의에 따르면 하네스는 무엇인가?
    하네스는 모델을 제외한 나머지 전부다. 지시문은 프롬프트, 토큰 전체는 컨텍스트이며 둘 다 하네스 안에 포함된다.
    Q2다음 중 사용자가 직접 더하는 부분에 해당하는 것은?
    도구 실행·권한·문맥 불러오기는 Claude Code·Codex 같은 도구가 기본으로 준다. 규칙·스킬·훅·검사 도구는 사용자가 작업에 맞게 더한다.
    Q3“스킬을 필요할 때만 불러오기”는 어느 고리에 처음 포함되는가?
    모델이 보는 토큰을 무엇으로 채울지 고르는 일이므로 컨텍스트 엔지니어링이다. 컨텍스트는 하네스에 포함되므로 하네스 엔지니어링이기도 하지만, 처음 포함하는 가장 안쪽 고리는 컨텍스트다.
